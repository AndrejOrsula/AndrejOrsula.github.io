pyo3_bindgen

Automatic generation of Rust FFI bindings to Python modules via PyO3.

pyo3_bindgen generates Rust FFI bindings to Python modules via PyO3. It walks a module recursively and emits Rust code with the same structure for all public classes, functions, properties and constants, keeping docstrings and type annotations where they exist. Rust code then calls Python through typed functions instead of string-based attribute lookups. This helps to integrate a Python project with Rust, or to move it to Rust step by step.

The image above shows a real example: a small orbit.py module and an excerpt of what pyo3_bindgen -m orbit generates for it. The float annotations become f64, the docstrings become Rust doc comments, and the module constant MU_EARTH gets a getter and a setter.

Features

  • Build script: call pyo3_bindgen::Codegen from build.rs, optionally customized with pyo3_bindgen::Config, and include! the generated file.
  • Procedural macro (experimental): import_python!("math") with the macros feature generates bindings in place.
  • Command line: cargo install --locked pyo3_bindgen_cli, then pyo3_bindgen -m os sys numpy -o bindings.rs to inspect bindings for any importable module.
  • NumPy (experimental): the numpy feature maps NumPy arrays to the numpy crate’s PyArray.

Status

The latest release is pyo3_bindgen 0.5.0 (May 2024) on crates.io, dual-licensed under MIT or Apache 2.0. It targets the Bound<'py, T> API introduced in PyO3 0.21; version 0.4 remains available for the older GIL-Refs API.

Limits to know:

  • Speed: the generated code calls into Python, so it is not faster by itself. It is a typed starting point for rewriting the slow parts in Rust.
  • Coverage: bindings are only as complete as the module’s structure, annotations and docstrings, and not every Python type has a Rust mapping yet.
  • Stability: the API of the generated bindings may still change.

Used by blr

blr is a Rust interface for Blender’s Python API. Its upcoming version uses pyo3_bindgen to generate typed bindings to Blender’s API, with a Rust layer for authoring scenes on top. A showcase of such scenes will be published with that version; a preview is below.

The interactive viewer is not available on this site. The image above shows native Blender renders from the blr showcase.

The published blr 0.1.0 release predates this work: it uses PyO3 directly and targets Blender 3.6.
